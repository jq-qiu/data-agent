# 产品范围：MVP V1

## 1. 产品目标

面向经营分析人员提供一个单轮数据分析入口，使用户既能用自然语言查询指标，也能对已确认的 GMV 异动进行受控诊断。

系统的价值不是替代 BI 或证明因果关系，而是把以下人工分析步骤组织成可追溯流程：

```text
理解指标和范围
→ 查询并确认异常
→ 拆解指标变化
→ 按维度定位变化贡献
→ 查询候选经营因素
→ 校验证据与能力边界
→ 生成诊断结论
```

## 2. 目标用户

- 希望直接用自然语言查数的业务人员；
- 需要快速定位经营指标异动的数据分析人员；
- 维护指标口径、数仓和分析链路的数据开发人员。

## 3. V1 用户问题

### 3.1 开放问数

- 某月 GMV 是多少；
- 各品类 GMV 排名；
- 某州订单量趋势；
- 某时间范围商品、客户、卖家等多表查询。

### 3.2 对比和诊断

- 某月 GMV 相比基期变化多少；
- GMV 变化主要来自订单量还是 AOV；
- 哪些州、品类贡献了主要下降；
- Traffic、Promotion、Inventory 是否存在同向异常；
- 当前数据不足以继续诊断时，还缺少哪些证据。

## 4. 能力分级

| 等级 | 能力 | V1 |
|---|---|---|
| L1 | 指标查询与描述 | 支持 |
| L2 | 趋势和期间对比 | 支持 |
| L3 | 指标恒等式拆解 | 支持 |
| L4 | 互斥维度变化贡献 | 支持 |
| L5 | 候选因素关联验证 | 支持 Traffic、Promotion、Inventory |
| L6 | 严格因果推断 | 不支持 |

## 5. V1 功能范围

### 5.1 In Scope

- 单轮 Query API；
- QUERY/DIAGNOSIS 意图识别；
- Olist DWD 多表查询；
- Metadata、Metric Registry、Qdrant 和 Elasticsearch 检索；
- SQL 生成、只读校验、执行与有限纠错；
- 诊断问题结构化解析；
- 静态与运行时能力判断；
- 最多四类诊断任务：期间对比、指标拆解、维度贡献、候选因素验证；
- Controlled Analytical SQL；
- 确定性计算；
- Validated Evidence 和 Markdown/JSON 报告；
- 30 条 NL2SQL 与 10 条诊断回归评测。

### 5.2 Out of Scope

- “那圣保罗州呢？”等依赖历史语义的省略式多轮追问；
- 登录、租户、复杂权限和企业任务平台；
- 上传任意附件并自动执行内容；
- 任意系统命令执行；
- 自动补货、调价、营销投放等外部写操作；
- 价格、退款、配送等 V1.1 候选因素；
- 无上限自主规划和无限下钻；
- 将关联证据表述为确定因果；
- 生产 SLA 和生产泛化能力声明。

## 6. 核心成功条件

V1 成功不是“报告听起来合理”，而是：

1. 指标公式、表字段和 JOIN 来源明确；
2. SQL 在固定数据上返回正确结果；
3. 指标拆解与维度贡献可以数学对账；
4. 每个关键数字和结论有证据来源；
5. 没有数据时主动降级，不猜测业务原因；
6. 固定评测集能够复现结果并定位错误层次。

## 7. 语言边界

无因果识别条件时允许：

- “贡献了整体变化的……”；
- “与 GMV 下降在时间和切片上具有一致性”；
- “是当前优先候选因素”；
- “现有证据支持关联诊断”。

无因果识别条件时禁止：

- “导致”；
- “造成”；
- “证明”；
- “唯一原因”；
- “采取该措施一定能够提升”。

## 8. 数据真实性说明

- Olist 订单、商品、客户、卖家、支付、物流和评价为匿名公开数据的转换结果；
- Traffic、Promotion、Inventory 和 Business Event 为用于功能验证的合成数据；
- 合成字段必须明确标记，不得包装成原始真实业务数据；
- 地域保持巴西州级语义。
