# 05. 归因方法、证据与结论分级

## 1. 方法定位

本系统默认回答的是经营指标的**变化贡献与诊断线索**，不是自动证明因果关系。

- “华南门店贡献了总体下降的 62%”可以由加法恒等式核算；
- “缺货率上升与销量下降同时出现”属于相关性证据；
- “缺货导致销量下降”是因果陈述，必须依赖随机实验或满足假设的准实验。

任何归因报告都应把“观察、贡献、相关、因果”分开表达。

## 2. 分析前置条件

在计算贡献之前必须锁定：

1. 指标定义及版本；
2. 当前期和基线期；
3. 业务时区、币种、税口径和退款口径；
4. 分析范围和权限过滤；
5. 数据粒度、数据水位与质量状态；
6. 指标树的选中分析路径；
7. 可接受的绝对误差与相对误差。

当前期与基线期必须可比。未完成的“本月”不得直接与完整“上月”比较；节假日、星期结构、开店天数明显不同，应对齐后再分析或作为限制披露。

定义总体变化：

```text
ΔY = Y_current - Y_baseline
relative_change = ΔY / |Y_baseline|
```

当 `Y_baseline = 0` 时不计算常规变化率，输出绝对变化并标记 `baseline_zero`。

## 3. 加法贡献分解

### 3.1 定义

若父指标可以按互斥且完备的成员相加：

```text
Y = Σ Yi
```

成员 `i` 的变化贡献为：

```text
contribution_i = Yi_current - Yi_baseline
```

对账关系：

```text
Σ contribution_i + residual = ΔY
```

`residual` 只能来源于“其他”合并、四舍五入、未知成员或数据版本差异，必须单独展示，不能偷偷分摊给主要项。

### 3.2 贡献率与排序

当分析下降原因时，先按与总体变化**同方向**的贡献绝对值排序。推荐同时输出两个比例：

```text
net_share_i = contribution_i / ΔY
directional_share_i = |contribution_i| / Σ|同方向 contribution|
```

`net_share` 可能大于 100%：例如 A 门店下降 120 万，B 门店增长 20 万，总体下降 100 万，A 的净贡献率为 120%。这不是错误，应同时展示抵消项，避免只报百分比。

### 3.3 合法性条件

- 维度成员在当前期和基线期使用相同映射；
- 成员互斥，且包含未知/其他成员；
- 分组后总值能与父指标对账；
- JOIN 没有改变事实表粒度；
- 不跨维度累加贡献。

例如门店分解与品类分解都是总体 GMV 的两种视角，不能把两者的贡献相加后声称解释了 200%。

## 4. 乘法指标的 Shapley 分解

### 4.1 两因子精确公式

对 `Y = A × B`，如：

```text
GMV = paid_order_count × AOV
```

从基线 `(A0, B0)` 变化到当前 `(A1, B1)`。若按替换顺序计算，交互项的归属会依赖顺序。使用两种顺序的平均，即 Shapley 分解：

```text
φA = (A1 - A0) × (B0 + B1) / 2
φB = (B1 - B0) × (A0 + A1) / 2
```

并且：

```text
φA + φB = A1×B1 - A0×B0 = ΔY
```

示例：基线订单数 1,000、客单价 100 元；当前订单数 900、客单价 105 元。

```text
ΔGMV = 900×105 - 1000×100 = -5,500 元
φ订单数 = (900-1000)×(100+105)/2 = -10,250 元
φ客单价 = (105-100)×(1000+900)/2 = +4,750 元
```

结论应为：订单数下降贡献 `-10,250` 元，客单价提升抵消 `+4,750` 元，净变化 `-5,500` 元。

### 4.2 多因子公式

对 `Y = f(x1, …, xn)`，因子 `i` 的 Shapley 贡献为其在所有替换顺序中的平均边际变化：

```text
φi = Σ[S⊆N\{i}] |S|!(n-|S|-1)!/n! ×
     (f(x_current on S∪{i}, x_baseline otherwise)
      - f(x_current on S, x_baseline otherwise))
```

- `n ≤ 8` 时可枚举全部子集或排列并精确计算；
- `n > 8` 时使用固定随机种子的排列采样，输出采样数和误差估计；
- 所有因子必须来自已登记指标树，禁止 LLM 临时构造恒等式；
- 计算后必须验证 `Σφi ≈ ΔY`。

### 4.3 零值、负值和单位

Shapley 的值域分解可处理零值和部分负值，但业务解释需谨慎：

- 因子为比率时必须限制合法区间；
- 基线因子为零时不输出因子相对贡献率，只输出绝对贡献；
- 如果指标公式包含 `min/max`、分段规则或口径切换，使用通用函数 Shapley，而不是套用两因子公式；
- 不使用对数分解处理非正数；
- 每个 `φi` 的单位与父指标相同，而不是因子自身单位。

## 5. 比率与漏斗指标

### 5.1 比率

对于 `R = numerator / denominator`：

1. 先检查分子、分母是否使用相同范围和粒度；
2. 同时展示两期分子和分母；
3. 用通用两因子 Shapley 对函数 `f(N,D)=N/D` 分解，但 `D=0` 的组合不可计算；
4. 存在零分母时，降级为分子/分母描述分析并标记限制；
5. 不对门店转化率直接求平均，应先汇总分子分母再相除。

### 5.2 漏斗

漏斗节点至少记录进入人数和阶段转化率。例如：

```text
支付人数 = 访问人数 × 访问到点击率 × 点击到加购率 × 加购到支付率
```

可使用多因子 Shapley 分解各阶段对支付人数变化的贡献。各阶段必须采用同一用户去重规则、归因窗口和事件顺序。

## 6. 维度下钻策略

下钻优先级由业务配置决定，不能只让 LLM 自由选择。推荐流程：

1. 对指标树一级子指标分解；
2. 对同向贡献最大的子指标按允许维度下钻；
3. 每个维度保留 Top N 同向项、主要抵消项和“其他”；
4. 对达到最小样本量且贡献超过阈值的切片生成假设；
5. 关联库存、价格、促销、退款、渠道等证据源验证假设；
6. 达到覆盖率或预算上限后停止。

默认建议参数：

```yaml
attribution:
  top_n: 5
  min_sample_size: 30
  min_abs_change: 0
  min_relative_change: 0.05
  target_directional_coverage: 0.80
  reconciliation_abs_tolerance: 0.01
  reconciliation_relative_tolerance: 0.0001
```

阈值必须按指标类型配置，以上仅为开发默认值，不代表通用业务标准。

## 7. 混杂、重叠与常见误区

### 7.1 维度重叠

同一事实可同时属于门店、品类、渠道。系统应把不同维度标为独立的 `analysis_view`，每个视图分别与总体变化对账，不跨视图相加。

### 7.2 辛普森悖论

总体趋势可能与分组趋势相反。重要结论至少检查一个已知混杂维度，如门店结构、客户新老结构或渠道结构，并在发现反转时明确说明。

### 7.3 选择偏差和幸存者偏差

横向比较门店时，应按门店类型、开业时长和营业天数匹配；仅分析仍营业门店可能低估关闭门店影响。

### 7.4 季节性与促销日历

食品零售受星期、节假日、天气和促销影响明显。基线无法对齐时，只能输出“可能关联因素”，不能把自然季节变化归因给运营动作。

### 7.5 数据问题伪装成业务问题

订单延迟、退款回补、维表拉链错误、编码变更和重复 JOIN 都可能造成异常。数据质量 gate 必须先于业务归因。

## 8. 证据模型与充分性评分

### 8.1 证据硬门槛

任一硬门槛失败，证据不得支持主结论：

- `traceable = true`：存在快照、文件片段或实验报告引用；
- `authorized = true`：来源和数据范围已授权；
- `metric_consistent = true`：指标版本、时间和过滤口径一致；
- `freshness_status != stale`：或已明确接受陈旧数据；
- `sample_size >= configured_minimum`：小样本只能作提示；
- 数值能够被确定性复算。

### 8.2 评分维度

硬门槛通过后，以 0～1 计算：

| 维度 | 权重 | 含义 |
|---|---:|---|
| `source_quality` | 0.25 | 权威指标层/受控实验高于自由文本 |
| `relevance` | 0.20 | 是否直接对应当前指标、范围和时期 |
| `temporal_alignment` | 0.15 | 原因变化是否早于或同步于结果变化 |
| `magnitude` | 0.15 | 变化规模是否足以解释结果 |
| `consistency` | 0.15 | 不同切片和时间窗口是否一致 |
| `corroboration` | 0.10 | 是否有独立来源相互印证 |

```text
evidence_score = Σ(weight × dimension_score) × quality_penalty
```

`quality_penalty` 在 `(0,1]`，由缺失率、数据延迟、估算值比例等规则产生。最终分数由代码计算，LLM 只能给出各维度建议和理由，规则引擎负责裁剪与汇总。

### 8.3 结论门槛

建议默认：

- `< 0.45`：不得进入主要结论，仅列为待验证线索；
- `0.45～0.64`：`descriptive` 或弱 `associational`；
- `0.65～0.79`：可形成 `associational` 或经对账的 `contributory` 结论；
- `≥ 0.80`：高可信贡献/相关结论，但仍不能自动升级为因果；
- `causal`：除分数外，还必须通过第 9 节的因果设计门。

单一总分不能替代硬门槛和人工判断，报告必须展示关键评分理由。

## 9. 相关与因果分级

| 等级 | `claim_level` | 可以说 | 不可以说 |
|---|---|---|---|
| L0 | `descriptive` | “GMV 较基线下降 8%” | “由库存造成” |
| L1 | `associational` | “缺货率上升与销量下降同期出现” | “缺货导致下降” |
| L2 | `contributory` | “订单数下降对 GMV 变化贡献 -10,250 元” | 把恒等式贡献当干预效应 |
| L3 | `causal` | “在给定假设下，促销使销量提升约 X” | 隐藏实验假设或外推限制 |

### 9.1 因果设计门

只有以下之一且通过设计检查，才允许 `causal`：

- 随机对照实验/A-B 测试；
- 差分中的差分（平行趋势、无同步干预等假设）；
- 回归不连续（阈值不可操纵、局部连续性）；
- 工具变量（相关性、排除限制、单调性）；
- 合成控制或匹配设计（可比性、干预前拟合等）。

结果必须包含 `causal_assessment`：设计类型、处理组、对照组、估计量、置信区间、关键假设、诊断结果和适用范围。仅有时间先后、相关系数或 LLM 常识不能通过因果设计门。

## 10. 假设验证

每个假设按下列模板执行：

```text
假设：华南 GMV 下降主要与核心商品缺货有关。
可观察预期：缺货商品销量下降更大；缺货发生早于或覆盖下降时段；
             非缺货商品不应出现同等幅度下降。
所需数据：SKU-门店-日库存、可售状态、销量、价格、促销。
反向证据：库存充足切片也出现相同下降，或销量下降早于缺货。
判定：supported / partially_supported / refuted / unresolved。
```

判定规则：

- `supported`：主要预期成立，存在直接证据，且没有足以推翻的反向证据；
- `partially_supported`：部分切片成立或存在未控制混杂；
- `refuted`：核心可观察预期不成立；
- `unresolved`：缺失数据、样本不足或证据冲突。

`supported` 仍只表示当前结论等级下得到支持，不等同于因果成立。

## 11. 输出与措辞规则

推荐结论句式：

```text
[观察] 本月华南 GMV 较对齐基线下降 5,500 元（-5.5%）。
[贡献] Shapley 分解显示，订单数变化贡献 -10,250 元，客单价变化抵消 +4,750 元。
[下钻] 门店 A、B 合计覆盖同方向下降的 68%。
[相关] 两店核心 SKU 缺货率同期上升，与销量下降存在一致关联。
[限制] 尚缺少促销变更记录，不能确认缺货是唯一原因，也不能作严格因果判断。
```

禁用无证据措辞：“肯定是”“完全由于”“根本原因”“证明了”，除非因果设计和证据确实支持。建议使用：“贡献了”“与……一致”“相关联”“优先排查”“在当前证据下”。

## 12. 结果验证

发布前必须自动验证：

- 当前值、基线值和变化值能复算；
- 每个分解视图的贡献和残差能对账；
- 排名、正负方向、单位和百分比一致；
- 所有结论引用真实 `evidence_id`；
- 反向证据没有被遗漏；
- 结论等级通过对应门槛；
- `causal` 结论包含完整因果评估；
- 缺失数据和停止原因出现在限制中；
- 自然语言中的所有数字均存在于结构化结果。

## 13. 最小测试集

1. **加法对账**：三个门店含增长抵消项，验证净贡献率可超过 100%。
2. **两因子 Shapley**：使用第 4.1 节示例，验证贡献和为 `-5,500`。
3. **基线为零**：不产生无穷变化率。
4. **比率零分母**：降级为描述分析并产生限制。
5. **跨维度防重**：门店贡献与品类贡献不被相加。
6. **数据未完成**：质量 gate 阻断业务归因。
7. **小样本**：证据不能支持主要结论。
8. **证据冲突**：假设状态为 `partially_supported` 或 `unresolved`。
9. **因果越级**：无实验设计的“导致”措辞被校验器拒绝。
10. **可复现**：同一快照、配置和随机种子得到相同贡献结果。
